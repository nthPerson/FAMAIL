# Experiments run ledger

Committed reproducibility ledger for the experiments-section campaign
(`docs/superpowers/plans/2026-07-11-experiments-section.md`). **Nothing runs without a
ledger row**: every campaign run is wrapped by
`python -m famail_temporal.analysis.run_ledger start|finish`, which appends/patches a row
here, writes `<artifact-dir>/environment.json` (python/torch/CUDA/GPU + pip-freeze hash),
and on `finish` appends SHA-256 checksums of `<artifact-dir>/*.json` + `*.npz` to
`<artifact-dir>/PROVENANCE.md`.

Columns:

| column | meaning |
|---|---|
| queue | campaign queue id (Q0–Q8 stages) or `B*` for backfilled pre-campaign artifacts |
| status | `LAUNCHED` → `DONE` (live rows); `DONE (backfilled)` / `RUNNING (backfilled)` for pre-campaign rows; `DIED (…)` / `ABORTED (…)` / `KILLED (…)` mark launches that never finished — each is explained in the Campaign events section |
| start (UTC) | row-append time (live) or what the artifact preserves (backfill; dir-name timestamps are local) |
| end (UTC) | `finish` time (live) or the artifact's recorded `timestamp_utc` (backfill) |
| wall | end − start (live) or the artifact's recorded runtime (backfill; `-` if not preserved) |
| git | short SHA at launch (backfill: the artifact's recorded `git_sha`; `(dirty)` as recorded) |
| frozen-gate | `PASS` iff `git diff main -- famail_temporal/algorithm/ famail_temporal/evaluation/runner.py` is empty at launch; `n/a` for backfill (not evaluated at run time) |
| config | config/feature-set note + environment-capture note |
| artifact dir | results directory |
| command | exact command (backfill: transcribed verbatim from the artifact's manifest/metrics/run-book) |

## Campaign events (chronological — the story behind every non-DONE row below)

> **Q1-CPU-ABORT (2026-07-12 UTC):** q1 CPU-companion attempt ABORTED after ~8.8h — the iFGSM arm
> is LSTM-heavy and ~50x slower on CPU than GPU (no partial artifacts written). q1 reverted to
> --device auto; runs on GPU immediately after r4. Concurrency lesson: CPU companions suit
> CPU-bound scoring, not discriminator-heavy attacks. (Row `Q1-arm-ifgsm` → ABORTED.)

> **HOST-SLEEP EVENT (2026-07-12 ~06:1x UTC):** Windows host slept mid-campaign (dmesg: time-jump +
> dxg ioctl failures); eGPU dropped; r4 (WBC, seed 4/6) and q5-SZ (variance) both died with NO
> artifacts written — r4 interior progress lost (~8h, no mid-run checkpoint). r1/r2a/r2b markers
> intact. Relaunched both; preventive: disable host sleep for the remainder of the campaign.
> (Rows `R4-wbc-shz` / `Q5-shz` started 2026-07-11T21:19 / 2026-07-12T05:39 → DIED.)

> **WSL-RESTART (2026-07-12 ~06:45 UTC):** after the host-sleep relaunch (06:41/06:42 rows), Robert
> restarted WSL2 to clear the eGPU state before committing to the long runs; those two just-launched
> processes died with it and were re-launched cleanly at 06:47 (the rows that went on to DONE).
> (Rows `R4-wbc-shz` / `Q5-shz` started 06:41:53 / 06:42:07 → DIED.)

> **GPU-OVERSUBSCRIPTION EVENT (2026-07-13 00:1x UTC / 2026-07-12 ~17:15 PT):** Q3 (SZ L1v2) as a
> guarded companion beside R4 (SZ WBC, seed 5/6) filled the 8 GB card (7,902/8,192 MiB) → WSL
> shared-memory spillover thrashed R4 badly: its seed-5 `random_w10` arm took 17,740 s (~4.9 h)
> vs 575–1,580 s for all prior arms. **Deliberately KILLED Q3 after 6h33m (no artifacts lost — none
> existed; Robert approved)** to let R4 finish at normal speed; Q3 relaunched SOLO post-R4
> (2026-07-13T00:46:58Z row). Retro-note: the June SZ L1v2 anchor is ~8.5h solo
> (`level1_table_v2/cleaned_5seed/timings.jsonl` = 30,562s), so the killed attempt was likely part
> healthy-long-run, part contention — the kill remains justified by R4's measured 30x degradation.
> **Doctrine amendment:** combined-VRAM pairing budgets must be measured PER CITY — the 3.8 GB
> "L1v2 companion" figure was SF-only; SZ L1v2 is far larger and does NOT fit beside WBC.
> (Row `Q3` started 2026-07-12T17:37:12Z → KILLED.)

> **Q1-GPU-CRASH (2026-07-13 04:49 UTC):** first-ever GPU execution of the perturbation arms died
> 30 s in: `RuntimeError: cudnn RNN backward can only be called in training mode` — the frozen
> eval-mode Siamese discriminator's LSTMs hit cuDNN's no-backward-in-inference restriction when the
> attack differentiates through them (never seen before because the arms had only run on CPU, where
> cuDNN is not involved). Fixed in `stifgsm_baseline.py` by recording the differentiated forward
> under `torch.backends.cudnn.flags(enabled=False)` (native kernels, same math; no-grad scoring
> keeps the fused kernels), with a CUDA-gated LSTM regression test written first and watched fail
> with the exact production error. (Row `Q1-arm-ifgsm` 2026-07-13T04:49:29Z → FAILED; relaunched
> after the fix.)

> **Q1-RECOUNT-UNEXECUTABLE (2026-07-13 06:28 UTC):** run-book step 2's per-arm
> `supply_recount --persist-grids` crashed on the first arm: the tool's tier-1 pass hard-requires
> the EDITOR's `delta_supply_3d.npz`, which perturbation arms never produce (latent run-book bug,
> unexecuted until now). The tier-2 grids it computed before crashing persist in the arm dir; no
> paper cell consumes a per-arm tier-1 recount, and `histories.pkl` preserves the raw material for
> any later supply analysis. Driver patched to SKIP recount for dirs without the editor artifact.
> (Row `Q1-recount-…ifgsm…` → FAILED; the five Q1-arm rows and Q1-ext are unaffected.)

> **NVITOP-MISHAP (2026-07-14 00:02 UTC / 2026-07-13 ~17:02 PT):** an accidental double-click in
> nvitop's TUI killed both GPU processes: Q6b's editor (~3.5 h into ~13 h, no checkpoints) and
> R5b's rollout (~5 h in, minutes from finishing). Both relaunched ~17:04 PT via the documented
> recipes (chain relaunch is skip-if-done; stale companion lock cleared with ps-verification).
> R5b's rerun completed 22:53 PT (row below, DONE 5:47:59); Q6b's rerun is the 00:04:20Z row.
