# Spec — Data Cleanup (T7) + Full Experiment Re-Run with Paper-Data Enrichment

**Date:** 2026-06-25 · **Status:** approved design, ready for implementation plan.
**Owner:** Robert Ashe · **Context:** FAMAIL, KDD push (abstract Jul 19, paper Jul 26). See `famail_temporal/baselines/MEETING_40_PREP.md`, memory `[[meeting40-plan]]`, `[[pickup-gps-sinks]]`.

## 0. Why

The gradient-heatmap audit found **6 per-driver "stuck-GPS" pickup sinks** in the raw taxi data (a frozen meter-on coordinate emitting ~10–12k phantom pickups per driver). The editor's **attribution selects the most-unfair cells**, so these phantom-concentration cells are heavily over-selected (Robert reported ~38% of *attributed* trajectories sink to them — to be reconciled). Therefore **attribution itself is polluted**, which is why we must clean the data *before* any further experiments rather than after. F_causal (headline) is essentially unaffected (Δ+0.0004); the artifact distorts the secondary F_spatial only (cell (28,52): 0.082→0.101, +23%).

This spec covers: the filter, source-data regeneration, re-running the **existing** experiment suite on clean data, and re-deriving every figure/artifact — **with an enrichment layer** that persists paper-grade data along the way.

## 1. Scope

**In scope:** stuck-GPS filter; regenerate `source_data/` + preprocess cache; re-run editor; re-run L1-v2, L2, weighted-BC+placebo, variance suite, Data Pareto; regenerate all figures; the enrichment captures in §6.

**Out of scope (separate follow-on):** the new Meeting-40 experiments — T1 (top-K **most**-fair ablation), T4–T6 (fine-tuning). This re-run produces the **clean substrate** they build on. They get their own spec/plan once this lands.

## 2. Decisions (locked)

1. **Filter rule = Hybrid (data-driven + guard).** Data-driven coordinate-concentration detection, **plus an assertion** that the flagged cell set equals the 6 known sinks — fails loudly if the rule drifts on regeneration.
2. **Discriminator = reuse frozen + re-verify gate.** Keep `discriminator_checkpoints/default/best.pt`; rely on each run's validation gate to confirm it still passes (~0.84/0.17) on cleaned data. Retrain only if the gate fails.
3. **Costly extras = L1-v2 multi-seed error bars only.** Skip editor `--diagnostics` (α-term figure) and the multi-seed edit-delta envelope.
4. **All free/cheap enrichment captures = included** (§6).
5. **Preserve before/after:** cleaned results write to **new `*_cleaned` dirs**; never overwrite dirty artifacts.
6. **Defaults:** weighted-BC grid = 6 seeds × w{10,20,30} + `--placebo 10,30`; **retire** L1-v1 and `metric_hardening` on clean data (legacy / subsumed by variance suite); **drop** (not suppress) phantom pickup pings *pending* the Stage-0 dry-run confirming whether they also carry `active_taxis` empties.

## 3. Principles

- **Correctness-gated:** a verification check between every stage; no blind proceed (§7).
- **Don't guess — validate with data:** thresholds + drop-vs-suppress finalized from the Stage-0 dry-run, not pre-chosen.
- **TDD** the filter and the new persistence schemas.
- **Provenance:** stamp every cleaned artifact with the cleaned-data fingerprint + edit-dir path + git SHA.

## 4. Grounded facts (from code investigation — cite before trusting)

- **Injection point:** `data/source_generation/event_stream.py`, inside `build_event_stream`, **after** quantization + weekday-drop + sort (~line 46) and **before** `add_transition_columns`/`assign_segment_ids` (lines 48–49). This is the only place exact `latitude`/`longitude` + `plate_id` + `x_grid`/`y_grid` coexist (`views/trajectories.py:52-56` drops lat/lon). Detect pickups via **raw `passenger_indicator` 0→1 per driver** (`is_pickup` does not exist yet; created later by `transitions.py:15-34`). After dropping flagged rows, transitions/segments recompute on the cleaned df.
- **Counts are rebuilt from surviving trajectory endpoints** (`cli.py:95-105`), so removing phantom pickups flows through automatically.
- **Systemic invariant #6** (`invariants.py:186-188`) raises if `n_drivers != 50` — verify no sink driver is fully removed.
- **`preprocess --force` is required** (`preprocess.py:51-57`) or stale cache is kept.
- **Every downstream `--edit-dir` defaults to the OLD `2026-05-28…causal_emphasis_no-dedup` dir** and MUST be repointed to the new cleaned edit-dir.
- **`gradient_viz_bundle.npz` is a stale static BEFORE-EDIT cache** (2026-06-18) — it does NOT auto-refresh; must be regenerated by `precompute` or it silently shows pre-cleanup sinks.
- **1 RTX 3070 = exactly one GPU job at a time.** Stage-4 GPU jobs serialize; CPU analysis/figures overlap for free.

> All exact CLI flags below are grounded in the investigation but **confirm with `--help`** before each run in case of drift.

## 5. Pipeline (phased)

### Stage 0 — Filter + dry-run (CPU, dev; user/PI-gated)
- Implement `filter_stuck_gps_sinks(df, *, thresholds…)` in `event_stream.py` at the injection point above. Hybrid rule: group pickup events by `(plate_id, round(lat,6), round(lon,6))`; flag groups exceeding a count threshold AND with ≥~0.99 single-driver/single-coord cell dominance; **drop** flagged pickup rows; **assert** flagged cells == `{(28,52),(20,28),(28,28),(24,5),(22,46),(17,38)}`.
- TDD: catches the 6 sinks; drops only flagged rows; keeps 50 drivers; no-op on clean input.
- **Dry-run** that persists the **per-(driver,coord) concentration distribution** (top-K) + whether flagged coords carry `passenger_indicator==0` empties.
- **GATE:** flagged set == 6 known cells; thresholds chosen from the distribution; drop-vs-suppress confirmed. Do not proceed otherwise.

### 6.1 Provenance & reproducibility bundle (free/cheap — from gap review; ⏳ = wire BEFORE Stage 3)

The baseline runners currently persist **no** provenance (the editor + source-gen stamp git SHA; the baselines don't). These bind every headline number to an exact code state, dataset, and invocation — load-bearing for the KDD artifact/reproducibility expectations and the Sept rebuttal.

- **E19 ⏳** — per-run **`manifest.json`** in every cleaned out-dir: `{git_sha, git_dirty, sys.argv, seeds, edit_dir actually used, hostname, timestamp_utc}`. ## 7. Verification & correctness

- **TDD:** filter detection (catches 6 sinks, drops right rows, keeps 50 drivers, no-op on clean); each new persistence field (schema present + shapes).
- **Inter-stage gates:** as in §5.
- **Sanity invariant:** F_causal results ~unchanged (Δ small); F_spatial *rises* at the sink cell. A material F_causal shift = STOP + investigate.
- **Repoint guard:** a checklist (or a small assertion) that every Stage-4 run used `<NEW_EDIT_DIR>`, not the May-28 default.
- **Before/after comparison:** since cleaned results land in `*_cleaned` dirs, diff each headline number dirty-vs-clean and record in a short `CLEANUP_DELTA.md` (itself paper material).

## 8. Parallelization schedule

CPU stages (0–2) serial. Stage 3 (editor) runs alone (~2h), blocks all Stage-4 GPU jobs. Then serialize GPU jobs in §5 order; **while each GPU job runs, run the Stage-4a CPU analysis + Stage-5 figure exports concurrently** (CPU/RAM only, no 3070 contention). `run_data_pareto --edit-from-dir` is CPU (use it, not `--with-edit` which is GPU). GPU critical path ≈ Stage1+2 (minutes) → Stage3 (~2h) → serialized {L1-v2 multi-seed, weighted-BC ~5–7h, L2 ~3h, variance ~1h+}.

## 9. Timeline (compute; dev time separate)

Stage 0 dev+dry-run (hours) → 1–2 CPU (**to be timed**: minutes–tens of minutes) → 3 GPU ~2h → 4 serialized GPU (~15–20h incl. L1-v2 multi-seed) with CPU overlap → 5 CPU (minutes). Runtimes marked "to be timed" are not derivable from code and will be measured live.
